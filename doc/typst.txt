==============================================================================
INTRODUCTION                                                *typst-introduction*

typst.nvim is a project-aware Typst workflow plugin for Neovim.

The plugin is inspired by VimTeX's workflow model: identify the project and
main document, run builds asynchronously, surface diagnostics, open viewers,
offer navigation, and keep editing commands close to the source language. It is
not a TeX compatibility layer. Typst has different project structure, output
formats, diagnostics, preview tools, and semantic tooling, so typst.nvim uses
Typst-native concepts where a direct VimTeX port would be misleading.

A Typst buffer usually belongs to a project keyed by a root directory and a
main document. The current buffer does not have to be the main document:
included files, package-style libraries, and unnamed scratch buffers can still
resolve to the document that should be compiled, viewed, indexed, or searched.

The most useful first command is usually: >

  :TypstInfo
<

It shows the root, main file, output, compiler provider, Tinymist state,
diagnostics policy, active watcher/process details, and the source of the
root/main decision. Use `:TypstInfo!` for the same data in a scratch buffer.

==============================================================================
FEATURE OVERVIEW                                                *typst-features*

Core workflow:

- project attachment for Typst buffers, including root/main-file discovery;
- one-shot compile, continuous watch, stop, status, logs, and cleanup;
- compiler diagnostics through `vim.diagnostic` and quickfix;
- viewer opening plus capability-gated forward and inverse source jumps;
- native browser/viewer preview plus optional typst-preview.nvim compatibility.

Navigation and document understanding:

- project file lists, layered TOC, labels, citations, symbols, and pickers;
- `gf`-style following for imports, paths, packages, labels, citations, URLs,
  and local/imported definitions;
- syntactic project index with Tinymist overlays where semantic data exists;
- package resource browsing and generated symbol/emoji information.

Editing support:

- heading, block, equation, raw-block, and comment motions;
- Tree-sitter and optional Tinymist text objects;
- Typst-aware surround, markup, label/reference, list, raw, equation, and
  argument-list transforms;
- folds, indentation, conservative prose `formatexpr`, matching-pair
  navigation/highlighting, and optional conceal.

Completion and metadata:

- omnifunc plus native, nvim-cmp, and blink.cmp adapter APIs;
- labels, references, citations, imports, paths, CSL styles, packages,
  templates, raw languages, colors, fonts, symbols, emojis, local definitions,
  and generated stdlib metadata;
- optional Tinymist completion requests when a Neovim LSP client is attached.

Extensibility:

- public Lua API namespaces for projects, compiler, viewer, artifacts, editing,
  completion, metadata, syntax, conceal, bibliography, and providers;
- provider registry for compilers, viewers, pickers, TOC/index layers,
  formatters, linters, grammar checkers, workflows, and renderers;
- `TypstEvent*` User events for setup, project, compile, preview, view, render,
  TOC, and quit lifecycle hooks.

REQUIREMENTS                                                *typst-requirements*

Required:

- Neovim 0.11+
- `typst` executable in `PATH`

Recommended:

- SeniorMars/tree-sitter-typst for structural editing, text objects, folds,
  indentation, conceal, package syntax extensions, and syntax-aware fallback
  indexing;
- Tinymist when semantic completion, hover, document symbols, code actions,
  rename previews, inlay hints, document links, and color information are
  desired;
- typstyle for the default non-Tinymist formatter path;
- a browser, configured PDF viewer, custom preview provider, or optional
  typst-preview.nvim compatibility for source-map-style synchronization;
- Telescope, fzf-lua, fzf.vim, Snacks, or `vim.ui.select` for picker UIs;
- optional external tools such as textidote, vlty/Vale-style checkers,
  crityp, or terminal image support depending on configured workflows.

Run `:checkhealth typst` after installation. Health output reports executable
availability, parser/query loading, Tinymist and preview integration state,
configuration, and attached project state.

==============================================================================
SETUP                                               *typst-setup* *typst-start*

Minimal setup: >

  require("typst").setup()
<

Setup should run during normal startup before opening Typst buffers if you want
non-default configuration. Defaults are still available when a Typst ftplugin
loads first, but calling setup early makes the intended configuration explicit.

Useful small setups: >

  -- Use Tinymist only when another plugin has already attached it.
  require("typst").setup({
    integrations = {
      tinymist = { lsp = "detect" },
    },
  })

  -- Write output next to the main Typst file and open it with zathura.
  require("typst").setup({
    output_dir = "",
    viewer = { provider = "zathura" },
  })

  -- Tune large-project indexing and path completion caps.
  require("typst").setup({
    project = {
      index = {
        large_file_policy = "headings-only",
        max_file_bytes = 512 * 1024,
      },
    },
    completion = {
      path_scan_cache_ms = 1000,
      path_scan_entry_max = 500,
    },
  })
<

Run `:checkhealth typst` to inspect executable availability, parser/query
loading, Tinymist and preview integration state, configuration, and attached
projects. Project health lines include provider-aware status, root/main
decision sources, project-specific Tinymist attachment, effective compiler
diagnostics policy, active profile, command, cwd, and process/watcher details
when present.

==============================================================================
DAILY WORKFLOW                                                     *typst-usage*

Most sessions use a small command loop: >

  :TypstInfo
  :TypstSetMain path/to/main.typ
  :TypstWatch
  :TypstView
  :TypstPreview
  :TypstToc
  :TypstPick labels
  :TypstStop
<

`:TypstInfo` is the diagnostic command for the plugin itself. If the wrong file
is being compiled, inspect `root_source` and `main_source` there before changing
configuration.

Use `:TypstSetMain` in included files when automatic discovery cannot know the
intended compile root. Use `:TypstToggleMain` to switch the current buffer
between local-main mode and normal project-main resolution.

Use `:TypstWatch` for a VimTeX-like continuous compile workflow. Use
`:TypstCompile` for a one-shot build, and `:TypstCompileSS` when a VimTeX muscle
memory alias is useful. Use `:TypstErrors` or `:TypstDiagnostics` to open the
current compiler diagnostics in quickfix.

Use `:TypstView` for generated output and `:TypstPreview` for browser preview.
Typst PDF output does not provide SyncTeX by default, so forward and inverse
search are only enabled for viewer or preview backends that explicitly declare
the relevant capability.

For navigation, start with `gf`, `:TypstToc`, and `:TypstPick`. For editing,
the default motions, text objects, dot-repeat-aware structural transforms, and
insert helpers are documented under |typst-mappings| and |typst-editing|.

PROJECT MODEL                         *typst-projects* *typst-main-resolution*

typst.nvim keeps project state per resolved `(root, main)` pair, not globally
per Neovim session and not simply per buffer. This allows multiple unrelated
Typst documents, or multiple main documents under one repository, to be open at
the same time with different output paths, watchers, diagnostics, TOC state,
and preview/viewer state.

Project resolution order:

1. `vim.b.typst_main`
2. saved explicit `:TypstSetMain` choice
3. `// typst.nvim: main = ../main.typ` comment directive
4. configured `main` string, callback, or per-root table mapping
5. nearest `.typstmain` project file
6. existing project dependency graph
7. capped local `#include`/`#import` scan
8. nearest root marker plus `main.typ` for nested files
9. current buffer

Unnamed Typst buffers attach to a scratch in-memory project rooted at the
current working directory. `:saveas` re-resolves them as normal file-backed
projects and prunes the scratch project. Scratch project main paths are
internal identity keys, not readable Typst files. The built-in CLI compiler and
watcher reject scratch projects with an actionable error; save the buffer first
before running |:TypstCompile|, |:TypstWatch|, |:TypstPreview| in compile mode,
or other file-backed workflows. Stdin-backed fragment compiles such as
|:TypstCompileSelected| are the deliberate exception: they send generated
source to `typst compile -` and do not compile the synthetic scratch path.

Root-level Typst files under the same root marker can resolve as independent
main documents instead of all falling back to a sibling `main.typ`; the
`main.typ` heuristic is reserved for nested files after stronger sources fail.

`:TypstSetMain` persists the explicit choice for the current buffer path so it
survives later Neovim sessions. When a buffer is renamed with `:saveas`, the
saved choice follows the new buffer path. Set `project.persist_main = false` to
ignore saved choices. Unreadable explicit main paths are ignored during
resolution; stale `vim.b.typst_main` values are cleared so import scanning and
current-buffer fallbacks can recover after a main file is deleted or moved.
Project state records `dependency_sources` and `file_sources` values of
`explicit`, `compiler`, or `heuristic`; existing graph attachment uses that
priority order so heuristic associations do not override explicit or
compiler-discovered project membership.

The syntactic project index is persistent per project. It caches each scanned
Typst or bibliography file by loaded-buffer changedtick or on-disk mtime/size
plus the active index policy. `project.index.max_file_bytes` limits unloaded
file static indexing. `project.index.large_file_policy = "skip"` omits
oversized unloaded files, `"headings-only"` reads the file to recover headings
and local imports/includes while skipping heavier symbol/reference scans, and
`"scan"` fully scans oversized files. Unnamed Typst buffers use their scratch
project main path as the index key and are rescanned by buffer changedtick, so
fallback headings, labels, references, definitions, and TODOs work before the
buffer has a file name.

Typst buffers detach on `BufUnload`, `BufDelete`, and `BufWipeout`, and on
`BufHidden` when the buffer's `bufhidden` policy will unload, delete, or wipe
it. Retained hidden buffers stay attached. When the last buffer leaves a
project, typst.nvim stops any active one-shot compile or watcher before
removing that project from the registry.

==============================================================================
COMPILATION AND DIAGNOSTICS
                                      *typst-compile* *typst-compile-lifecycle*
                                      *typst-watch* *typst-output-locks*

The built-in compiler provider runs the Typst CLI without a shell. The global
`executable` may be a string such as `"typst"` or a list prefix such as
`{ "uv", "run", "typst" }`; typst.nvim appends the Typst subcommand and
arguments itself.

One-shot compiles and watchers are mutually exclusive per project. Starting a
watcher stops an active one-shot compile, and starting a compile stops an active
watcher. `:TypstStopAll` walks every registered project and stops active
compiler state without requiring the current buffer to belong to that project.

Watch mode records each parsed compile cycle separately. Each cycle gets a
monotonic `cycle_generation`, updates diagnostics for that cycle, refreshes
dependency knowledge when dependency output is enabled, and notifies viewer and
preview reload hooks. Human-readable Typst watch output is parsed as
fixture-gated best-effort compatibility; structured JSON-line watch output can
be configured through `compile.watch_structured_args`.

Diagnostics are published through `vim.diagnostic`. With the default
`diagnostics.source = "fallback"`, compiler diagnostics are suppressed when a
Tinymist Neovim LSP client is attached for the project or coc.nvim appears to
own the Typst LSP session. Use `"always"` to keep typst.nvim compiler
diagnostics active alongside Tinymist, or `"off"` to turn them off.

Use these commands when a build behaves unexpectedly:

- |:TypstInfo| for the resolved project, command, cwd, provider, output, and
  diagnostic policy;
- |:TypstCompileOutput| for the last compiler command, stdout, stderr, and
  exit code;
- |:TypstLog| for broader plugin logs;
- |:TypstStatusAll| for all registered projects.

==============================================================================
VIEWERS AND PREVIEW
                                      *typst-view* *typst-preview-native*
                                      *typst-source-sync*

`:TypstView` opens the resolved generated output. By default this uses
`vim.ui.open`; named viewer presets and custom `viewer.open` callbacks or
commands can replace it. Viewer commands may use placeholders such as
`{output}`, `{main}`, `{root}`, `{line}`, and `{column}` in configured args.
Successful one-shot compiles notify `viewer.reload(project, result, opts)` and
`preview.refresh(project, result, opts)` with `opts.source == "compile"`.
Watch cycles notify the same hooks with `opts.source == "watch"` and
`opts.watch == true`. `:TypstCompile!` and `:TypstWatch!` request viewer
opening through typst.nvim rather than delegating output opening to Tinymist or
the Typst CLI.

`:TypstPreview` is the preview side of the workflow. It can call a configured
preview provider, use typst.nvim's native browser shell, or open the configured
viewer. Preview opens are project-aware, so running preview from an included
file still uses the resolved main document.

`preview.export.mode = "compile"` displays the artifact recorded by the compiler
service. `preview.export.mode = "profile"` runs a named `exports.profiles`
entry before display, and `preview.export.mode = "provider"` invokes an export
provider with a reserved output path. Preview exports are typst.nvim-owned and
are recorded with `producer = "preview"`; they do not replace the compiler
output path. Export providers receive `preview = true`, `preview_export = true`,
`preview_target`, and `update_compiler_output = false`. If no preview export
output directory is configured, typst.nvim writes into the preview cache with a
project-specific name. Browser refresh exports are generation-guarded so stale
exports cannot replace a newer active preview route.
`preview.browser.export.mode = "inherit"` makes the browser target use the
top-level preview export contract. |:TypstInfo| and |:TypstClean| distinguish
document artifacts from preview-owned cache exports. Preview-owned artifact
records also retain their preview export target, mode, profile/provider, and
format so |:TypstArtifacts|, |:TypstInfo|, and health can report preview cache
exports separately from document exports.
Browser artifact responses larger than `preview.browser.max_artifact_bytes`
return `413 Payload Too Large`; under-cap artifacts are streamed in bounded
chunks. Setting it to `0` disables the cap for trusted local use.
`preview.browser.style.variables` overrides browser-shell CSS custom
properties, `preview.browser.style.css` appends trusted inline CSS, and
`preview.browser.style.css_path` loads an absolute or project-relative
stylesheet. Keep shared styles under XDG config, such as
`stdpath("config")/typst.nvim/preview.css`. Variable keys without a leading
`--` are exposed as `--typst-preview-{key}`.
`preview.cache.max_entries`, `preview.cache.max_bytes`, and
`preview.cache.ttl_ms` prune stale preview-owned cache exports after preview
profile/provider exports. Active browser output is preserved. Use
|:TypstCleanPreview| for explicit preview-cache cleanup; bang forces deletion
of changed-but-owned preview artifacts while still preserving the active preview
output.

Native browser and external viewer validation is tracked in
`docs/preview-viewer-matrix.md`. Use `just preview-matrix browser-server` to
exercise the default URL opener, or use a named browser/PDF target such as
`safari`, `chrome`, `skim`, `sioyek`, `zathura`, `okular`, or `evince` when
that application is installed and you want an app-specific check.
Browser opener failures keep the attempted URL in preview state, in
`g:typst_nvim_last_preview_url`, and in |:TypstPreviewStatus| with bang. For
WSL, SSH, containers, and remote Neovim sessions, configure
`preview.browser.commands` with command lists such as
`{ "wslview", "{url}" }` or open the reported URL manually. Binding
`preview.browser.host` to a non-loopback interface requires
`preview.browser.allow_remote = true`; only enable it on trusted networks.
Remote browser routes include a token by default through
`preview.browser.token = "auto"`, or you can set a fixed non-empty token. With
`preview.browser.app = nil` and `preview.browser.commands = nil`, typst.nvim
uses `vim.ui.open()` when available, then the OS default URL opener such as
`open`, `xdg-open`, or Windows shell openers. Set `preview.browser.app` to
`"firefox"`, `"chrome"`, `"safari"`, `"edge"`, `"brave"`, or another
app/executable name only when a specific browser should be used. Use
`preview.browser.reload_throttle_ms` to limit watch refresh frequency for slow
browsers. `preview.browser.performance = "safari"` opts into file-shell
transport, slower polling, and reload throttling; `"fast"` lowers the browser
poll interval for SVG-oriented preview profiles. The default browser poll
interval is 250ms. The native browser shell exposes reload, zoom, fit, page,
status/error, and source-sync controls without taking over Tinymist's semantic
features.

Native typst.nvim preview only:
>
  require("typst").setup({
    preview = {
      provider = "native",
      native = "browser",
      follow_buffer = true,
      source_maps = {
        provider = "typst-query",
      },
      browser = {
        performance = "fast",
        export = {
          mode = "profile",
          profile = "preview_svg",
        },
      },
    },
  })
<

typst-preview.nvim for live preview, typst.nvim for workflow:
>
  require("typst").setup({
    preview = {
      provider = "typst-preview.nvim",
      native = "viewer",
    },
  })
<

In the hybrid setup, use typst-preview.nvim for its live/incremental browser
frontend and typst.nvim for root/main ownership, compile/watch/view, export
profiles, bibliography, navigation, health, logs, and cleanup.

Forward and inverse synchronization are capability-gated. PDF viewers do not
claim SyncTeX-style support by default because normal Typst PDF output does not
carry SyncTeX data. Native browser preview uses the default `typst-query`
provider for SVG browser outputs only; unsupported formats report no native
browser source-sync capability unless another provider supplies it. Legacy
`preview.forward`, `preview.inverse`, and `preview.capabilities` remain
supported; new source-map integrations should prefer
`preview.source_maps.provider`, `forward`, `inverse`, and `capabilities`.
Browser preview source-map workflows, including explicit typst-preview.nvim
compatibility through `TypstPreviewSyncCursor`, are the Typst-native equivalent
of VimTeX's galley preview workflow.

Registered source-map integrations use the `source_map` provider kind. A
provider may implement `forward`, `inverse`, `generate`, `resolve`, or
`browser_inverse`. Native browser server mode sends DOM/SVG click coordinates
to `browser_inverse` through its local `/source-sync` route and opens the source
location returned by the provider. PDF plugin clicks and file-shell fallback
tabs cannot be intercepted by typst.nvim.

Rendered previews are explicit actions, not automatic inline rendering on every
edit. Commands such as |:TypstPreviewFragment|, |:TypstPreviewEquation|,
|:TypstPreviewImage|, and |:TypstPreviewPage| compile small artifacts into the
render cache and show them through the configured render display provider.

==============================================================================
NAVIGATION AND CONTEXT                                         *typst-navigation*

typst.nvim combines three sources of navigation data:

- Tree-sitter and syntactic project scans for headings, labels, citations,
  imports, paths, definitions, TODOs, and local structural context;
- Typst compiler dependency output for project membership after compiles or
  watch cycles;
- Tinymist semantic data for document symbols, definitions, references, rename,
  code actions, and LSP UI features when available.

Use `gf` or |:TypstFollow| for cursor targets. It understands local imports,
included files, image/data/bibliography paths, local CSL styles, Typst package
imports, URLs, labels, references, citations, and local/imported definitions.

Use |:TypstToc| for a persistent outline window or TOC-owned quickfix list.
The TOC can include headings, figures, tables, equations, labels, references,
citations, imports, files, TODOs, definitions, and custom provider layers.

Use |:TypstPick| for picker-backed access to the same normalized project and
TOC item model. The default picker tries Telescope, fzf-lua, fzf.vim, Snacks,
then `vim.ui.select`.

Use |:TypstContextMenu| for local actions under the cursor. The menu reuses
the same project, package, symbol, path, citation, label, color, font, and
semantic resolvers that power navigation and completion.

==============================================================================
COMPLETION AND METADATA                                      *typst-completion*

typst.nvim installs `v:lua.typst_nvim_omnifunc` for Typst buffers when no other
omnifunc is already set. Completion frontends can use the same fallback engine
through `require("typst").completion.native()`, `.cmp()`, `.blink()`,
`.cmp_source()`, and `.blink_source()`.

When a Tinymist Neovim LSP client is attached and the current context is
semantic Typst source, completion asks Tinymist for `textDocument/completion`
first. Pass `include_tinymist = false` to Lua completion calls to use only the
typst.nvim fallback sources.

Fallback completion combines project-index data and bundled metadata. It
covers labels, references, bibliography keys, local and imported `#let`
definitions, filesystem paths, package and template specs, built-in stdlib
items, named parameters, accepted parameter values, CSL styles, raw-block
language IDs, colors, fonts, symbols, and emojis.

The generated metadata is compact and versioned. It is meant to provide fast
completion, signatures, symbols, emojis, and conceal data; Tinymist remains the
semantic hover and language-documentation source.

==============================================================================
EDITING MODEL                                  *typst-editing* *typst-conceal*

Editing helpers are buffer-local and conservative. They prefer parser-backed
ranges, refuse incomplete syntax when preserving source would be uncertain, and
use Tinymist code actions only for features where semantic actions are a better
source of truth.

The default motions work in normal, visual, and operator-pending modes and
respect counts. Text objects cover headings, sections, equations, delimiters,
content/code/raw blocks, calls, arguments, labels, imports, and optional
list-items. Empty inner text objects and incomplete syntax return no range
rather than selecting stale text.

Structural transforms such as argument splitting/joining, label/reference
toggles, markup toggles, equation conversion, raw conversion, list toggles, and
surround operations are dot-repeat-aware. typst.nvim keeps multi-token edits in
one undo step and preserves user registers where practical.

Conceal is syntax-aware but not semantic Typst evaluation. Built-in symbol
conceal is suppressed when a local declaration or import could shadow a
stdlib meaning. With `conceal.reveal = "node"`, the source form is revealed
only under the current window's cursor while neighboring matches stay concealed.
Use `conceal.reveal = "line"` to reveal the cursor line, `conceal.reveal_insert`
to override Insert-mode behavior, and `conceal.reveal_by_category` for
category-specific reveal policy.

                                                        *:TypstInfo*
:TypstInfo[!]
    Show the detailed current-project report for the current buffer, including
    root, main, compiler provider, root/main decision sources, output, status,
    process working directory, last command, active compile PID, active watcher
    command, viewer backend/command, preview backend/command, dependencies, and
    diagnostics state. It also shows the active semantic provider, whether
    typst.nvim can see a Tinymist Neovim LSP client for the project, and
    whether compiler diagnostics are active, always enabled, off, or suppressed
    by semantic-provider ownership. The status value is read through the active

                                                        *:TypstWatch*
:TypstWatch[!] [profile]
    Start or restart continuous compilation for the resolved project. With
    bang, open the output through typst.nvim's configured viewer after the
    first successful cycle. With a profile name, apply the matching
    `compile.profiles` entry for this watcher. If a one-shot compile is active,
    it is stopped before the watcher starts. While the watcher is running,
    typst.nvim refreshes dependency knowledge from Typst's dependency output so
    included files can resolve to the watched main document. Each Typst watch
    compile cycle emits compile started/success/failure events, replaces stale
    diagnostics for that cycle, and keeps the project status in the watching
    lifecycle until the watcher is stopped. Each cycle also gets a monotonic
    `cycle_generation` that keeps increasing across watcher restarts.
    If the watch process exits after parsed cycles, typst.nvim keeps the last
    cycle as the build result instead of synthesizing another compile success or
    failure from the process exit.
    Typst's default watch output is human-readable, and Typst CLI 0.15 does not
    expose a stable structured watch-status flag, so that parser is
    fixture-gated best-effort compatibility. Configure
    `compile.watch_structured_args` when a future Typst executable or wrapper
    can emit stable JSON-line watch events. Set
    `compile.watch_output = "structured"` to reject human-readable status lines
    instead of parsing them.
    After a successful watch cycle, typst.nvim waits up to
    `compile.watch_output_wait_ms` for the expected output file to become
    readable before treating the cycle as a missing-output failure. Set it to
    0 to disable the wait; values above 60000 ms are rejected.
    Completed watch cycles notify optional viewer.reload(project, result, opts)
    and preview.refresh(project, result, opts) callbacks, with
    opts.source == "watch" and opts.watch == true.
    Retained watcher stdout/stderr is bounded. Unterminated partial-line
    buffers are bounded too.
    Repeated watch restarts while the old watcher is stopping are debounced
    into one replacement watcher.

                                                        *:TypstFollow*
:TypstFollow
    Follow the Typst target under the cursor. This is the command form of the
    default `gf` mapping. It resolves imports, image/data/bibliography paths,
    local CSL style files, package imports, URLs, labels/references, explicit
    `#cite(<key>)` citations, and local/imported definitions. Built-in CSL
    style IDs such as `ieee` are not treated as file paths. Tinymist definition
    is preferred for identifier targets when available; otherwise the syntactic
    project index is used.

    The syntactic project index is persistent per project. It caches each
    scanned Typst or bibliography file by loaded-buffer changedtick or on-disk
    mtime/size. Unnamed Typst buffers use their scratch project main path as
    the index key and are rescanned by buffer changedtick, so fallback headings,
    labels, references, definitions, and TODOs work before the buffer has a file
    name. The index reuses unchanged file records for headings, labels,
    citations, TOC layers, follow targets, package syntax extensions,
    completion, picker items, and context actions. Use `:TypstClearCache` or
    `require("typst").index.reset(project)` to drop cached index records.
    Bibliography parsing handles multiline/concatenated BibTeX fields and
    nested or inline Hayagriva YAML fields for citation metadata.
    Lua consumers that want semantic index data can call
    `require("typst").index.collect({ project = project, include_tinymist =
    true })`; this overlays Tinymist document/workspace symbols and their
    references onto returned headings, definitions, and references without
    changing the default syntactic cache. The call is cache-first and
    nonblocking: it returns the syntactic index plus any Tinymist cache that is
    still valid for the current project generation, and schedules an async
    refresh when semantic data is absent or stale.
    index providers extend the syntactic project index. Extension plugins can
    register `index` providers with
    `require("typst").providers.register("index", name, provider)`. Provider
    `collect(project, opts)` results are merged into normal index categories or
    normalized from an `items` list. Provider registration invalidates aggregate
    index caches, and `require("typst").index.mark_dirty(project, reason)` is
    available for provider-specific refreshes.
    `require("typst").bibliography.foldexpr()` and
    `require("typst").bibliography.indentexpr()` provide conservative BibTeX
    and Hayagriva helpers for integrations that attach bibliography buffers.
    `require("typst").bibliography.expanded_fields()` resolves BibTeX
    `crossref` and `xdata` inheritance. `search()` matches citation keys,
    author/editor, title, year/date, venue, keywords, and abstract text.
    `insert_text()` and `insert()` choose `@key`, `#cite(<key>)`, or `<key>`
    from the current Typst context. `open()`, `preview()`, `attachment()`,
    `attachments()`, `rename_key()`, and `status()` provide entry navigation,
    formatted citation summaries, configurable attached-PDF lookup,
    transactional citation-key rename, and project bibliography status
    summaries.

:TypstContextMenu

MAPPINGS                                                        *typst-mappings*

typst.nvim installs buffer-local defaults for Typst buffers:

Heading, block, equation, raw-block, and comment motions are available in
normal, operator-pending, and visual modes. They accept Vim counts such as
`2]m` and `3[[`.

Text objects follow the usual Vim `i`/`a` convention: inner selections remove
the surrounding syntax marker when that is meaningful, and outer selections
include the marker, delimiter, wrapper, or full syntax node.

Text object reference:

  Mapping   Kind               Inner selects           Outer selects
  `ih/ah`   heading            heading text            whole heading line
  `iH/aH`   section            section body            heading plus body
  `im/am`   equation           formula body            `$...$` or block math
  `id/ad`   delimiter          delimiter body          delimiter pair
  `ic/ac`   content            bracket body            `[ ... ]`
  `ib/ab`   block              nearest block body      nearest block node
  `ie/ae`   structural block   nearest unit body       nearest structural unit
  `iC/aC`   code block         code/raw contents       full code/raw block
  `ir/ar`   raw block          raw contents            full raw block
  `if/af`   function call      arguments/content       whole call
  `ia/aa`   argument           value/body              whole argument
  `il/al`   label/reference    label name              `@ref` or `<label>`
  `ii/ai`   import             import target/members   whole import statement

`ie` and `ae` are Typst structural-block objects, not TeX environments. They
target the nearest useful structural unit: function calls, bracket/content
blocks, code/raw blocks, equations, grouped expressions, arrays/dictionaries,
and list items. List-item objects exist as `<Plug>` mappings, but have no
default keys because the obvious `im/am` keys are used for equations.

typst.nvim does not currently provide VimTeX targets-style next/last text
objects such as `ine` or `ile`. Use motions like `]m`, `[m`, `]n`, and `[n`
with operators for directional selections.

==============================================================================
TREE-SITTER QUERIES                                           *typst-queries*

typst.nvim ships small query extensions for workflow features it owns:

- `queries/markdown/injections.scm`
- `queries/typst/textobjects.scm`
- `queries/typst/highlights.scm`
- `queries/typst/folds.scm`
- `queries/typst/indents.scm`
- `queries/typst/injections.scm`
- `queries/typst/conceal.scm`

The injection query captures Typst raw code blocks as embedded languages when
the block has a language tag, for example ` ```python `. The Markdown injection
query captures fenced ` ```typst ` blocks as Typst content when the Markdown
parser is available. The highlight query adds conservative captures for
headings, comments, markup styles, labels, references, list markers, raw text,
code calls, strings, numbers, math symbols, TODO/NOTE/WARN/FIXME comment
markers, parser errors, and punctuation without forking the parser.
It marks prose and comments with `@spell`, while raw spans/blocks, strings,
and math regions use `@nospell`.
The highlight query also sets Tree-sitter `bo.commentstring` metadata so
Neovim's built-in commenting can use `// %s` inside line comments and
`/* %s */` inside block comments.

The query suite is tested against `tests/fixtures/basic/syntax.typ`, a broad
fixture covering headings, documentation comments, imports, labels,
references, lists, markup styles, raw spans and blocks, calls, named
arguments, and inline/display math. This keeps core highlight, conceal,
text-object, fold, indent, embedded-Markdown, and injection captures tied to
parser-backed source rather than query-load smoke tests alone.

Syntax Reference                                      *typst-syntax-reference*

The highlight query intentionally uses common Neovim capture names so colors
come from the user's theme. The shipped captures are:

  Comments:
    `@comment`, `@comment.todo`, `@comment.note`, `@comment.warning`,
    `@comment.error`

  Spell checking:
    `@spell`, `@nospell`

  Markup:
    `@markup.heading`, `@markup.heading.1`, `@markup.heading.2`,
    `@markup.heading.3`, `@markup.heading.4`, `@markup.heading.5`,
    `@markup.heading.6`, `@markup.strong`, `@markup.italic`,
    `@markup.link.label`, `@markup.list`, `@markup.raw`,
    `@markup.raw.block`

  Typst labels, raw tags, and code:
    `@label`, `@string.special`, `@keyword`, `@keyword.import`,
    `@keyword.operator`, `@function.call`, `@variable.parameter`,
    `@string`, `@number`

  Math and punctuation:
    `@constant`, `@operator`, `@punctuation.special`,
    `@punctuation.delimiter`, `@punctuation.bracket`

  Malformed syntax:
    `@error`

The conceal query is structural. These captures are consumed by the Lua
conceal resolver and are not meant to be color groups:

  `@conceal.symbol`, `@conceal.emoji`, `@conceal.math_delimiter`,
  `@conceal.script`,
  `@conceal.markup_delimiter`, `@conceal.heading_marker`,
  `@conceal.list_marker`, `@conceal.raw_delimiter`, `@conceal.raw_block`,
  `@conceal.label_delimiter`, `@conceal.reference_marker`,
  `@conceal.function_wrapper`

typst.nvim intentionally does not use Tree-sitter highlight-query `conceal`
metadata for these replacements. The Lua conceal renderer owns category
toggles, metadata safety checks, shadowing checks, caching, and window-local
cursor reveal behavior that native highlight conceal cannot express.

The text-object query exposes these captures for query-aware text-object
plugins and for typst.nvim's mapping tests:

  `@heading.inner`, `@heading.outer`, `@section.inner`, `@section.outer`,
  `@equation.inner`, `@equation.outer`, `@content.inner`, `@content.outer`,
  `@block.inner`, `@block.outer`, `@structural_block.inner`,
  `@structural_block.outer`, `@code_block.inner`, `@code_block.outer`,
  `@raw_block.inner`, `@raw_block.outer`, `@list_item.inner`,
  `@list_item.outer`, `@label.outer`, `@import.outer`, `@call.inner`,
  `@call.outer`, `@argument.inner`, `@argument.outer`

The fold, indent, and injection queries expose `@fold`, `@indent.scope`,
`@indent.ignore`, `@injection.language`, and `@injection.content`.

The package-aware syntax extension layer is resolved in Lua from the project index
rather than by rewriting `queries/typst/highlights.scm`. When a buffer imports a
configured package spec, typst.nvim can highlight imported package entry points
with extmarks. The default configuration includes `@preview/cetz` and the
`TypstPackageCetz` highlight group. Use
`require("typst").syntax.package_extensions()` to list active package specs,
`require("typst").syntax.package_matches()` to inspect matched ranges, and
`require("typst").syntax.refresh()` to reapply package highlights after
changing configuration or imports.

The conceal query captures small structural candidates such as math identifiers,
dotted fields, explicit emoji fields, delimiters, scripts, and heading markers.
Lua resolves symbol and emoji names through versioned Typst metadata generated
from Typst's Rust library and keeps punctuation/script rules syntax-driven, so
the query does not contain a large symbol table.
Set `metadata_version` to a bundled Typst version such as `"0.14.2"` or
`"0.15.0"` to pin the metadata snapshot. Leave it as `nil` to use the newest
compatible bundled snapshot; `:TypstInfo` and health output report mismatches
when a requested or detected Typst version falls back to a different bundled
version.

When `folds.enabled` is true, Typst buffers use Typst fold settings. The
default mode is expression folding with heading fallback and Tree-sitter folds
when a compatible parser is available. `folds.mode = "manual"` leaves fold
creation to the user while still applying configured fold options. `folds.text`
may be a callback used by the installed `foldtext`.

When `indent.enabled` is true, Typst buffers install a buffer-local
`indentexpr`. The indentation logic uses the shipped indent query to preserve
raw-block contents and applies Typst-aware rules for delimiters, display math
fences, and list continuations. When `indent.formatexpr` is true, Typst buffers
also install a conservative prose/comment `formatexpr` for `gq`.

CONFIGURATION                                                      *typst-config*

`require("typst").setup()` validates the merged configuration before replacing
the active state. `require("typst.config").snapshot()` returns an isolated copy
for integrations that only need to inspect settings. `get()` returns a
read-only view for direct indexed reads. Use `snapshot()` when you need to
traverse or mutate a copy. `unsafe_get()` is for typst.nvim internals that
intentionally need the live table.

The runtime plugin calls `setup()` with defaults when `plugin/typst.lua` is
sourced. Later `require("typst").setup({...})` calls are reconfiguration:
commands, global autocmds, and plug mappings remain one-time runtime state,
while configuration is validated again and attached buffers are reapplied. Set
`vim.g.typst_nvim_no_auto_setup = 1` before plugin loading to opt out of the
default runtime setup and call `setup()` explicitly.

The complete generated default-key reference is in `docs/config-reference.md`
and the machine-readable schema is `data/config-schema.json`. Run
`just config-docs` after changing defaults.

Project and main-file resolution are explained in |typst-projects|. The
configuration keys that affect that model are `root_markers`, `main`,
`project.import_scan`, `project.import_scan_max_files`,
`project.import_scan_max_depth`, `project.import_scan_max_entries`,
`project.import_scan_max_descendant_depth`, `project.import_scan_skip_dirs`,
and `project.persist_main`.
`project.import_scan_skip_dirs` entries are directory basenames, not paths or
glob patterns. Use "build" rather than "build/" or "foo/build".

Set any mapping to `false` to leave it unbound, or set `mappings.enabled` to
`false` to disable all default Typst buffer mappings.
VimTeX-style workflow keys are configured through `mappings.commands`; for
example, `mappings.commands.watch = "<localleader>ll"` maps to
`<Plug>(typst-watch)`.
TOC buffer mappings are configured separately through `toc.mappings`. Set
`toc.mappings.jump`, `toc.mappings.preview`, `toc.mappings.close`,
`toc.mappings.refresh`, `toc.mappings.toggle`, `toc.mappings.toggle_layer`,
`toc.mappings.filter`, or `toc.mappings.clear_filter` to a key string, or set
an entry to `false` to leave that action unbound. `toc.visible_layers` controls
the initial layer
visibility for headings, figures, tables, equations, labels, references,
citations, imports, files, TODOs, and definitions.
`toc.follow_cursor` moves the open TOC cursor to the current source section,
and `toc.highlight_current` highlights that TOC entry. Cursor-follow updates
are debounced by `toc.follow_delay_ms`.
`toc.auto_refresh` refreshes an open TOC after attached source-buffer edits or
writes, delayed by `toc.refresh_delay_ms`.
Manual and automatic refreshes preserve the TOC cursor entry, collapsed headings,
filters, and per-project layer visibility.

Insert-mode <Plug> mappings have no default keys. Bind
`mappings.insert.strong`, `mappings.insert.emph`, `mappings.insert.math`,
`mappings.insert.content`, `mappings.insert.code`, or `mappings.insert.raw` to
insert paired Typst markup. The same helpers are available through
|:TypstInsert| and Lua functions such as `require("typst").edit.insert_math()`.

`diagnostics.source` controls compiler diagnostics:

- `"fallback"` publishes compiler diagnostics unless Tinymist owns diagnostics
  through Neovim's built-in LSP client or coc.nvim, or a custom semantic
  provider explicitly declares diagnostic ownership.
- `"always"` always publishes compiler diagnostics in typst.nvim's namespace.
- `"off"` disables compiler diagnostics.

Tinymist diagnostics are owned by Neovim's LSP client. typst.nvim's compiler
diagnostics are project/source namespaced and follow `diagnostics.source`;
health and `:TypstInfo` report whether they are active, suppressed by
semantic-provider ownership, always enabled, or off. Custom semantic providers
that only provide symbols, links, colors, or editor actions do not suppress
compiler diagnostics by default.

`diagnostics.list` controls where `:TypstDiagnostics` and automatic
`diagnostics.use_quickfix` publishing put compiler diagnostics. The default
`"quickfix"` uses the global quickfix list. `"loclist"` uses the current
window's location list, which is better when multiple Typst projects are open
in different windows.

`diagnostics.external_paths` controls how parsed diagnostics for unopened files
are handled. The default `"bufadd"` creates unloaded buffers up to
`diagnostics.max_buffers_per_publish` so `vim.diagnostic` can own those
diagnostics. `"quickfix-only"` avoids creating diagnostic buffers and keeps
those items only in the configured quickfix/location list when
`diagnostics.use_quickfix` is enabled; Neovim may still create its own buflist
entry for jumpable quickfix filenames. `"open-files-only"` publishes
diagnostics only for already loaded buffers and reports skipped external paths
in `:TypstInfo!`; use this for the strict no-new-buffer policy.
quickfix-only diagnostics are stored by diagnostic source so
`:TypstDiagnostics` can rebuild the list after another command replaces it.

Tinymist integration                                      *typst-tinymist*

`integrations.tinymist.lsp` controls typst.nvim's Tinymist Neovim LSP
integration. The default `"auto"` starts or reuses a Neovim built-in LSP client
named `tinymist` when the executable is available, unless coc.nvim appears
active. Set `integrations.tinymist.client_names` to also detect custom wrapper
client names. `"detect"` only queries an existing nvim-lsp Tinymist client,
`"off"` disables typst.nvim Tinymist LSP use, and `"start"` forces
nvim-lsp startup even when Coc is present. `integrations.tinymist.cmd`,
`path`, `settings`, `init_options`, `capabilities`, and `on_attach` configure
`vim.lsp.start()` for `"auto"` and `"start"`. `integrations.tinymist.path` is
the Tinymist executable path; `integrations.tinymist.cmd` overrides `path` with
a full command prefix for wrappers or extra arguments.
When using coc.nvim, including `coc-tinymist`, configure Coc's
`tinymist.serverPath` and `tinymist.serverArgs`; typst.nvim does not read Coc
settings or send requests to Coc's private LSP client.
`integrations.tinymist.capabilities` and `integrations.tinymist.on_attach` are
passed through to `vim.lsp.start()`. Tinymist CLI workflows such as
|:TypstTest| are separate from this LSP setting.
Citation completion is controlled separately by `bibliography.completion`.
The default `"auto"` keeps project-index citation completion for offline/no-LSP
sessions and `include_tinymist = false`, but avoids fallback citation candidates
when a native Neovim Tinymist client is attached or coc.nvim appears active. Use
`"project"` to force fallback citation completion, or `"tinymist"`/`"off"` to
suppress it.

Tinymist features are intentionally split between native Neovim LSP behavior
and typst.nvim wrappers:

- Native pass-through: semantic highlighting, hover, document highlights,
  folding ranges, inlay hints, and signature help should normally use Neovim's
  built-in LSP UI directly. typst.nvim may expose a small toggle or facade for
  tests/status, but it should not replace Neovim's renderer.
- Wrapped: completion, structural code actions, formatting, document links,
  document symbols, definitions, references, color reports, code lenses,
  rename preview/apply, workspace symbols, selection ranges, and diagnostics
  policy use typst.nvim wrappers where stale-result guards, project-index
  merging, report buffers, picker/context integration, or fallbacks matter.
- Plugin-owned: compile/watch, exports, artifact cleanup, template init,
  tests, benchmarks, coverage, lint workflows, statusline data, package
  resources, and profile reports are typst.nvim workflows. Tinymist may supply
  a provider or returned command, but it does not own the state model.

See `docs/tinymist_parity.md` for the full method-by-method matrix.

`format.provider` may be `"auto"`, `"tinymist"`, `"typstyle"`, `"command"`, a
registered provider name, callback, or a provider table exposing
`format(bufnr, project, opts)`. The default `"auto"` path asks Tinymist for LSP
formatting first when a Tinymist nvim-lsp client is attached or auto-started;
otherwise it falls back to `typstyle`. `format.command` may be a string
executable or list prefix and is run with buffer text on stdin. The `"prose"`
provider wraps plain Typst prose paragraphs with `format.prose_width` while
leaving headings, code, math, raw blocks, lists, and function/code lines
unchanged.

`lint.provider` may be `"typst"`, `"tinymist"`, `"command"`, a registered
provider name, callback, or a provider table exposing
`lint(bufnr, project, opts)`. The default `"typst"`
provider compiles to a temporary output and publishes parsed Typst human or
short diagnostics. The `"command"` provider receives current-buffer text on
stdin and parses stdout/stderr as short diagnostics relative to the project
root.

`grammar.provider` may be `"command"`, `"textidote"`, `"vlty"`, a registered
provider name, callback, or a provider table exposing
`grammar(bufnr, project, opts)`, `check(...)`, or `run(...)`. Generic commands
default to current-buffer text on stdin. `textidote` and `vlty` default to
passing the current file path. Arguments in `grammar.extra_args` may use
`{file}`, `{main}`, and `{root}` placeholders. `grammar.stdin` and
`grammar.file_arg` override those provider defaults. textidote line/column
output and Vale/vlty-style JSON output are normalized before diagnostics are
published.

`diagnostics.fonts` enables missing font-family warnings from
|:TypstFontDiagnostics|. The checker compares `font:` references with
configured `completion.font_families` and `typst fonts`.
`diagnostics.font_scan_timeout_ms = 0` skips the CLI font scan.

`structural_actions.patterns` controls how typst.nvim selects a Tinymist code
action for the structural commands. Patterns are Lua patterns matched against
the action title, kind, and command name.

`syntax.package_extensions` enables package-aware syntax highlighting.
`syntax.packages` maps package specs such as `@preview/cetz` to extension
metadata. Each package spec may set `enabled`, `name`, `capture`,
`highlight_group`, `priority`, and a `members` list. The package version in an
import is ignored for matching, so `@preview/cetz` covers imports such as
`@preview/cetz:0.3.4`. Matched package entry points are highlighted with
extmarks and can be inspected through
`require("typst").syntax.package_matches()`.

`conceal.enabled` controls the default for new Typst buffers. Commands can set
a buffer-local override. With `conceal.reveal = "node"`, reveal is window-local:
the candidate under the window's cursor is left as source text while
neighboring candidates remain concealed. `conceal.reveal = "line"` reveals all
matches on the cursor line, `conceal.reveal_insert` can override Insert-mode
behavior, and `conceal.reveal_by_category` can override specific categories.
`categories.math_symbols` enables built-in symbol conceal; `math_scripts`
enables conservative subscript and superscript replacements including
multi-digit scripts; `math_fonts` handles `cal(A)`, `bb(R)`, `frak(g)`, and
`bold(x)`; `math_operators` handles shorthand relations such as `<=`, `->`,
and `!=`; `math_wrappers` hides supported math wrapper syntax such as `abs(x)`
and `norm(x)`; `math_delimiters` and `markup_delimiters` hide only punctuation;
`function_wrappers` hides supported style-call wrappers such as `#strong[` and
]`; `emoji` hides explicit `emoji.*` symbols when explicitly enabled; `headings`
hides heading markers when explicitly enabled; `lists` hides list markers;
`raw_blocks` hides inline raw delimiters and fenced raw-block fences;
`raw_block_languages` hides raw-block language tags; `labels` hides shorthand
label delimiters; and `reference_markers` hides the leading `@` marker for
shorthand references/citations. The initial safety
defaults only allow an empty string or exactly one character, and that
character must pass display-width safety checks, so most emoji glyphs also need
`conceal.safety.max_display_width = 2`.
`conceal.custom.math` maps math names to custom replacements and is resolved
before generated Typst metadata. Runtime integrations can call
`require("typst").conceal.register("math", name, replacement)` and
`require("typst").conceal.unregister("math", name)`; runtime custom mappings
override config mappings. Resolved matches use cached lookup tables derived from
the active metadata/config/custom generations. They are cached per buffer,
changedtick, conceal generation, and conceal config, then filtered to the
visible range. Rendered viewport matches are cached per window so cursor
movement can reapply reveal policy without recollecting Tree-sitter matches.
Both caches are invalidated by edits and `:TypstConcealRefresh`. Implicit symbol conceal is
suppressed when a local `#let`, function parameter, explicit import binding,
import alias, or wildcard import makes the built-in meaning uncertain.
Shadowing uses a Tree-sitter lexical approximation that considers declaration order
and block/content scopes, not semantic resolution. Explicit `sym.*` symbols
still allow custom or built-in symbol resolution.
Explicit `emoji.*` symbols resolve through generated emoji metadata when
`conceal.categories.emoji` is enabled.

`compile.profiles` defines named per-run overrides for `:TypstCompile [profile]`
and `:TypstWatch [profile]`. A profile may set `output_dir`, `output_name`,
`output_format`, `extra_args`, `watch_output`, `watch_output_wait_ms`,
`watch_structured_args`, `deps`, `open`, and `typst_open`; these values do not
mutate the base configuration. Unsupported profile keys fail validation instead
of being silently ignored. `open = true` opens the successful output through
typst.nvim's configured viewer. `typst_open = true` passes Typst's raw `--open`
flag. When `deps = false`, typst.nvim does not refresh dependency knowledge for
that run and preserves the existing project graph.
`executable` may be a string such as `"typst"` or a list prefix such as
`{ "uv", "run", "typst" }`; typst.nvim appends the Typst subcommand and
arguments without going through a shell.

`validation = "warn"` records and logs unknown setup keys so typos such as
`diagnostic.source` do not silently disappear into the merged config. Use
`"strict"` to error on unknown keys, or `"off"`/`false` to disable the warning.

`output_name` controls the generated output filename. It must be a basename; use
`output_dir` for directories. If it has no extension, typst.nvim appends
`output_format`.
By default, output is written under `stdpath("cache")/typst.nvim/output`.
Set `output_dir = ""` to write next to the main Typst file, or set an explicit
relative path if you want project-local artifacts.

`compile.fragments` controls `:TypstCompileSelected`. The default template
names are `markup`, `math`, `code`, `full-page`, and `auto-sized`;
`document` and `auto` are compatibility aliases. Table templates concatenate
`prefix .. selection .. suffix`; string templates replace `{body}`; function
templates receive `(body, ctx)` and return either source text or a table with
template fields. Template tables may also override `output_dir`, `output_name`,
`output_format`, `extra_args`, `deps`, and `open` for the fragment run.
Fragment dependency capture is disabled by default so selected compiles do not
replace the parent project's dependency graph.
Fragment outputs default to `stdpath("cache")/typst.nvim/fragments`.
Generated fragment source is passed through stdin by default. The built-in
Typst provider runs `typst compile -` while `--root` remains the project root;
generic/task providers receive stdin and `{main}` expands to `-`; custom
provider callbacks can read the internal runtime field
`run_config.compile.stdin`. `compile.stdin` is not a public setup option.
Generic/task `{source}` still expands to the originating source path when it is
known, and `{stdin}` expands to `1` for stdin-backed fragment compiles.
Project-relative imports remain valid without writing wrapper files into the
project. Set
`compile.fragments.source_dir` or a template `source_dir` only when a compiler
provider needs a real temporary source file. File-backed fragment sources are
cleaned up after the fragment compile resolves or if the compiler provider
fails to start; output artifacts remain available.

`main` may be a string, callback, or table keyed by project root. Table values
may be strings or callbacks, allowing per-root main-file mappings while keeping
`vim.b.typst_main` as the highest-precedence override. Relative table keys are
normalized once during `setup()` against the setup-time cwd; later `:cd` or
`:lcd` changes do not change those mappings. A leading Typst comment directive
of the form `// typst.nvim: main = ../main.typ` resolves relative to the current
buffer. Throwing `root` or `main` callbacks are caught, logged, and treated as
no match so later resolvers can continue and the buffer is not left
half-attached. A `.typstmain` file contains the main path relative to that
file's directory, either as a bare path or `main = path`. When `root` is not
configured, table keys also act as root hints, so nested Typst projects can
resolve before a broader `.git` marker.

Project resolution records a main-file confidence label. Explicit sources are
high confidence, import-scan matches are medium confidence, and fallback
guesses such as current-buffer or nested `main.typ` are low confidence.
Existing-project graph matches inherit the matched project's original main
confidence; when no prior confidence is available they are treated as medium.
Compile/watch warn once per project before using the nested `main.typ`
heuristic unless `project.warn_on_low_confidence_main = false`. Other
low-confidence fallbacks are reported in |:TypstInfo!| but do not warn today.

`project.import_scan` enables a fallback scan for local `#include` and
`#import` statements that reference the current buffer. It is capped by
`project.import_scan_max_files` and `project.import_scan_max_entries`; when no
root marker is found, ancestor scanning is capped by
`project.import_scan_max_depth`. Package imports such as
`@preview/name:version` are ignored by this resolver.
Buffer attach defers this bounded scan: the buffer first attaches through the
later heuristic with `resolution_pending = "import_scan"`, then a scheduled
scan reassigns it if a unique importing main is found. Commands force a pending
scan before compile, watch, preview, or navigation uses the project.

Set `indent.enabled = false` to leave Typst buffer indentation untouched.

Example: >

  require("typst").setup({
    compile = {
      profiles = {
        draft = {
          output_dir = vim.fs.joinpath(vim.fn.stdpath("cache"), "typst.nvim", "draft"),
          output_name = "draft",
          output_format = "pdf",
        },
      },
    },
  })
<

`compile.provider` defaults to the built-in Typst CLI provider. Named providers
include `"generic"` and `"task"`, which run command arrays from
`compile.generic` or `compile.task`. Command arguments support `{root}`,
`{main}`, `{output}`, `{profile}`, `{provider}`, `{source}`, and `{stdin}`
placeholders. `{source}` matches `{main}` for normal document compiles; for
stdin-backed selected fragments it is the originating buffer path when
available. `{stdin}` is `1` only when the command receives generated source on
stdin. Advanced users may also set `compile.provider` to a registered provider
name, provider table, callback, or Lua module name. A provider must implement: >

  compile(project, callback, run_config)
  start(project, callback, run_config)
  stop(project, callback)
  status(project)
  output(project, run_config)
<

Project-specific task/generic providers are the Typst-native replacement for
Arara-style document automation. Configure `compile.provider = "task"` or
`"generic"` to route `:TypstCompile` and `:TypstWatch` through `just`, `make`,
`npm`, or another repository task runner without TeX directives in the source.

typst.nvim calls `output(project, run_config)` before custom `compile` and
`start` calls so events, `status()`, and `:TypstInfo` expose the provider's
output path.

typst.nvim tracks handles returned from custom `compile` and `start` calls in
the project compiler service as the active process or watcher. It also applies
standard lifecycle states from synchronous or asynchronous callback results.
Returned handles remain active until a provider result arrives, `stop()` reports
`stopped = true`, or failed shutdown moves the handle into retained-orphan
tracking. typst.nvim calls the provider's `stop()` method before starting the
opposite compile mode, and clears active handles when `stop()` reports
`stopped = true`. Calling `stop()` while no compile or watcher is active is
handled by typst.nvim without delegating to a custom provider; the
callback result still has `stopped = true` and additionally sets `idle = true`.
Provider callbacks should return a terminal table such as
`{ code = 0, stdout = ..., stderr = ... }` or `{ code = 1, message = ... }`,
or a pending table with `pending = true` while work is still owned. Terminal
non-stale results update `project.services.compiler.last_result`, status,
events, and output ownership consistently. `stopped = true` means confirmed
termination; `stopped = false` or `orphaned = true` keeps failed cleanup
visible. Retained orphans remain visible in reports/logs and keep leases guarded
until a real late exit releases them or the user runs an explicit reset/cleanup
path.

`viewer.provider` chooses the output viewer preset. The default `"generic"`
uses `viewer.open` when configured and otherwise falls back to `vim.ui.open`.
Built-in presets include `"zathura"`, `"sioyek"`, `"skim"`, `"sumatrapdf"`,
`"mupdf"`, `"evince"`, `"okular"`, and `"qpdfview"`. Presets can be overridden
through `viewer.providers.<name>`, and extension plugins can register viewer
names with `register_provider("viewer", name, provider)`. `viewer.open` may be
a Lua callback, a string executable, or a list prefix such as
`{ "python3", "viewer-wrapper.py" }`. When it is an executable prefix,
`viewer.args` is appended after the prefix and `{output}` placeholders are
expanded before the viewer command starts.

`viewer.forward` is capability-gated. It may be a callback, string executable,
list prefix, or `nil`; without it, |:TypstViewForward| tries a configured
`preview.forward` callback, then `:TypstPreviewSyncCursor` only when
`preview.provider = "typst-preview.nvim"`, and otherwise returns an unsupported
result. String and list-prefix commands return an unsupported result with
`detail = "capability_required"` until `capabilities.forward` or
`capabilities.source_maps` is declared.
Built-in PDF viewer presets open/reuse output but do not claim forward or
inverse synchronization by default because normal Typst PDF output has no
SyncTeX-style source map. `viewer.inverse` handles source locations reported by
source-map-capable viewers and uses `viewer.inverse_args` for executable
backends. String and list-prefix inverse commands use the same capability gate
with `capabilities.inverse` or `capabilities.source_maps`. If no inverse
backend is configured, |:TypstViewInverse| opens the reported source location
directly only when the selected viewer declares `capabilities.inverse` or
`capabilities.source_maps`. `preview.capabilities`
still declares browser preview source-map support for existing configs; new
integrations should prefer `preview.source_maps.capabilities` plus explicit
`preview.source_maps.forward`/`inverse` callbacks. |:TypstPreviewInverse| opens
source locations supplied by a preview/browser callback when inverse support is
available. Together these cover the galley-style browser preview source-map
workflow without pretending PDF output has SyncTeX.
For zathura, sioyek, Skim, and SumatraPDF, treat forward/inverse command args
as recipes: configure `viewer.forward_args`/`viewer.inverse_args`, then enable
`capabilities.forward`, `capabilities.inverse`, or `capabilities.source_maps`
only when a source-map provider can resolve Typst positions for that output.

Set `folds.enabled = false` to leave fold options untouched. `folds.foldlevel`
defaults to `99` so Typst documents do not open fully collapsed.

Tinymist owns semantic hover, definition, and language documentation. typst.nvim
does not provide a `texdoc` equivalent for Typst. Instead, it exposes generated
symbol/emoji information and package resources from cached manifests, READMEs,
source entrypoints, typst.nvim-specific optional `[tool.typst-docs]` resource
hints, package homepage/repository links, and Typst Universe pages.

Typst buffers install `v:lua.typst_nvim_omnifunc` as `omnifunc` when no other
omnifunc is already configured. In semantic Typst contexts, completion asks
attached Tinymist clients for `textDocument/completion` first. Pass
`include_tinymist = false` in Lua calls to skip the LSP request. The fallback
completion source combines a syntactic project index with the bundled symbol
and emoji metadata artifacts plus compact stdlib function, element, type, and
member metadata. It completes labels, references, bibliography keys, local `#let`
declarations, direct file imports, wildcard file imports, simple file
re-exports, local module-alias members, local `#include` `.typ` traversal,
referenced file paths, built-in stdlib names, explicit `std.*` and `math.*`
names, explicit `sym.*` symbols, and explicit `emoji.*` names.
Compact generated MessagePack metadata is bundled for built-in functions,
elements, types, parameters, returns, members, shorthands, constants,
categories, parameter details, and deprecations, without bundling a
package-documentation system. Named-parameter and signature fallback uses
generated stdlib signatures plus simple local/imported `#let function(...)`
signatures from the project index. In `#set` rules, generated stdlib
parameters are filtered to fields Typst marks as settable. Parameter
completion loads generated native parameter documentation lazily for menu
details.
Parameter-value
fallback uses generated CastInfo constants for accepted values such as
`image(fit: "cover")` or `text(style: "italic")`, and expands generated stdlib
constants for accepted value types such as `text(dir: rtl)` and
`align(alignment: center)`. Accepted value completions include Typst's
generated value-specific documentation when the stdlib exposes it. It also
scans cached Typst package roots
and optional local `completion.universe_index_paths` JSON files for `@...`
prefixes, returning exact package/template specs such as
`@preview/cetz:0.3.4`; template packages are labeled separately when their
manifest or index record contains template metadata. Inside path strings for
`#import`, `#include`, `image`, `bibliography`, `read`, and raw/data-style
calls, filesystem path completion scans the current directory level and returns
matching entries with context-sensitive extension filters. Inside
`bibliography(..., style: "...")` and `cite(..., style: "...")`, it completes
built-in Typst CSL style IDs, configured `completion.csl_styles`, and
project-local `.csl` files. Project-index glossary entries complete from
conservative `#let` glossary/acronym/term data, including dictionary-style
entry keys and `key: "..."` fields. In raw block fences such as
```` ```py ````, it completes common language IDs, configured
`completion.raw_languages`, and installed Tree-sitter parser names. In
color-like arguments such as `fill:` and `stroke:`, it completes generated
Typst stdlib color constants, configured `completion.color_names`, and
generated `color.map.*` presets. In `font:` arguments, it completes configured
`completion.font_families`, families discovered by `typst fonts`, and a small
embedded fallback set when the CLI scan is unavailable.
`completion.include_paths` disables filesystem path completion,
`completion.path_scan_entry_max` caps raw directory entries consumed per path
scan, `completion.path_scan_max` caps returned path completion items, and
`completion.path_scan_cache_ms` briefly caches path directory entries; set it
to `0` to disable that cache.
`completion.include_csl_styles` disables this source and
`completion.csl_scan_max` caps local `.csl` file discovery.
`completion.include_raw_languages` disables raw language completion.
Raw-language parser discovery and local `.csl` scans are cached by config
generation and expire after `completion.scan_cache_ttl_ms`; set it to `0` to
keep scan snapshots until config changes or `:TypstClearCache`.
`completion.include_colors` disables color completion.
`completion.include_fonts` disables font completion, and
`completion.font_scan_timeout_ms = 0` skips the `typst fonts` scan. Math
completion inserts unqualified symbol names such as `arrow.r`.
Completion frontends can consume the same fallback service through
`require("typst").completion.native(opts)`,
`require("typst").completion.cmp(opts)`,
`require("typst").completion.blink(opts)`, and small source objects from
`cmp_source(opts)` or `blink_source(opts)`.
`require("typst").completion.signature()` returns signature metadata from local/project
declarations or compact generated stdlib signatures, while Tinymist remains the
semantic hover/signature source.

Provider registration is the public extension registry. *typst-provider-contracts*
>

  require("typst").providers.register(kind, name, provider)
  require("typst").providers.unregister(kind, name)
  require("typst").providers.get(kind, name)
  require("typst").providers.names(kind)
  require("typst").providers.register(kind, name, provider)
<

Supported provider kinds are `compiler`, `format`, `lint`, `grammar`,
`viewer`, `preview`, `source_map`, `picker`, `toc`, `index`, `export`, `eval`,
`init`, `profile`, `test`, `bench`, `coverage`, `semantic`, and `render`.
Aliases such as `compile`, `formatter`, `linter`, `view`, `exports`,
`template`, `source_maps`, `sourcemap`, `benchmark`, and `terminal_image` are
accepted. Registered provider names are valid string values in the
matching config fields and per-call `opts.provider` where applicable.
`unregister_provider()` removes and returns the provider, `get_provider()`
inspects one registered provider, and `provider_names()` returns sorted names.
Provider return, callback, timeout, and cancellation rules are documented in
`docs/provider-contracts.md`.

`integrations.semantic.provider` selects the default semantic provider for
semantic actions, status reporting, and fallback compiler-diagnostic ownership.
It defaults to `"tinymist"` and accepts registered provider names,
inline provider tables, or callbacks. Semantic providers can implement
`color_info`, `document_links`, `code_lens`, `workspace_symbols`,
`references`, `rename_preview`, or a generic `run(method, project, opts)`
dispatcher; status helpers may expose `enabled`, `available_for_project`,
`mode`, `backend`, and `capabilities`. Custom semantic providers suppress
compiler fallback diagnostics only when they explicitly opt in with
`owns_diagnostics = true`, `diagnostics = true`, or a matching capability flag.

`picker.provider` controls |:TypstPick|. The default `"auto"` tries Telescope,
fzf-lua, fzf.vim, Snacks, then `vim.ui.select`. It may also be `"fzf_vim"` or
a registered provider name. Use `picker.provider = "custom"` with `picker.custom`, or call
`require("typst").picker.items()` directly, to feed the normalized project and
TOC items to another consumer. Custom TOC layer names registered by providers
can be passed as picker kinds and are returned as their own item kind.

VIMTEX PARITY AND TYPST DIFFERENCES                    *typst-vimtex-parity*

typst.nvim aims for VimTeX-style capability parity, not a literal TeX port.
The table below is a quick translation guide for users coming from VimTeX.

  VimTeX concept                  typst.nvim interpretation

  TeX root                        Typst `(root, main)` project state,
                                  |:TypstSetMain|, `.typstmain`, comments,
                                  dependency output, and import scanning.

  `latexmk` / compiler backend    |:TypstCompile|, |:TypstWatch|, custom
                                  compiler providers, export profiles, and
                                  process-owned diagnostics.

  Quickfix errors                 Compiler diagnostics through
                                  `vim.diagnostic` plus |:TypstDiagnostics|
                                  and |:TypstErrors| quickfix reports.

  SyncTeX                         Browser-preview source maps and explicit
                                  viewer capabilities. PDF forward/inverse
                                  search is enabled only when a backend
                                  declares support.

  Package detection               Typst package/import detection through the
                                  project index, cached package manifests,
                                  package resources, and package-extension
                                  providers.

  `texdoc`                        No direct Typst equivalent. typst.nvim uses
                                  package resources, cached READMEs/source,
                                  Universe links, generated symbol metadata,
                                  and Tinymist hover instead of a fake
                                  `texdoc` clone.

  LaTeX commands/environments     Typst calls, content/code/raw blocks,
                                  equations, headings, labels, imports,
                                  arguments, and structural blocks.

  Surrounding edits               Typst-native delete/change/toggle commands
                                  for calls, delimiters, equations, argument
                                  groups, labels/references, lists, raw text,
                                  figures, strong/emphasis, and line breaks.

  Insert-mode math shortcuts      Configurable Typst insert mappings through
                                  |:TypstImapsList| and the `imaps` Lua API.

  VimTeX TOC                      |:TypstToc| dedicated outline window or
                                  quickfix fallback, plus |:TypstPick|.

  LaTeX package syntax            Typst package-extension providers and
                                  project-index-driven package highlighting.

  Snippets                        Delegated to snippet engines. typst.nvim
                                  may provide examples or metadata sources,
                                  but it is not a snippet framework.

This deliberate boundary keeps typst.nvim closer to VimTeX's philosophy: own
project workflow, editing structure, navigation, conceal, and integration, but
compose with specialized tools where they are the better engine.

TROUBLESHOOTING                                        *typst-troubleshooting*

Start with these commands:

- |:checkhealth| `typst` for executable, parser, query, Tinymist, preview,
  configuration, and attached-project state;
- |:TypstInfo| or `:TypstInfo!` for root/main/output decisions, active
  compiler provider, Tinymist state, diagnostics policy, and watcher/process
  details;
- |:TypstCompileOutput| for the exact compiler command, cwd, stdout, stderr,
  and exit code from the last compile;
- |:TypstLog| for lifecycle, provider, and callback errors.

If the wrong document is compiled, inspect `root_source` and `main_source` in
|:TypstInfo|. Use |:TypstSetMain| for an explicit main, a `.typstmain` file for
project-local policy, or a `main` setup callback/table for editor-wide policy.

If no output opens, check `output_dir`, `output_name`, `output_format`, and the
viewer provider in |:TypstInfo|. With custom compiler providers, ensure the
provider's `output(project, run_config)` path matches the file the command
actually writes.

If |:TypstWatch| appears to run but preview does not refresh, inspect watcher
status, `watch_unknown_status_lines`, active output, and preview backend in
`:TypstInfo!`. Human `typst watch` output is parsed as a compatibility path and
can change between Typst versions; structured provider/watch output is more
stable when a provider supports it.

If Typst watch reports success but no output appears, check
`compile.watch_output_wait_ms`, `output_dir`, `output_name`, and filesystem
permissions. `compile.watch_output_wait_ms = 0` disables the delayed output
wait, which is useful for strict tests but can expose slow filesystem races.

If a custom compiler provider timed out while compiling, watching, or stopping,
|:TypstInfo| and health continue to show the active output lease. Use
|:TypstCompilerForceClear| only after you have handled the external process
yourself or accept that it may still be running.

If diagnostics appear twice, check `diagnostics.source`. The default
`"fallback"` publishes compiler diagnostics only when Tinymist is not attached
to the project through Neovim's built-in LSP client and coc.nvim does not appear
to own the Typst LSP session.

If compiler diagnostics disappear after Tinymist attaches, the same
`diagnostics.source = "fallback"` policy is usually the reason. Use
`diagnostics.source = "always"` when you intentionally want typst.nvim compiler
diagnostics beside Tinymist or another semantic provider.

If coc.nvim is active and native Tinymist did not start, configure
`coc-tinymist` through Coc settings such as `tinymist.serverPath` and
`tinymist.serverArgs`. Set `integrations.tinymist.lsp = "start"` only when
you intentionally want typst.nvim to start a separate nvim-lsp Tinymist client.

If an output path is already being written, another compile, watch, export, or
external provider still owns its lease. Use |:TypstStop| or |:TypstStopAll|,
inspect active leases in `:TypstInfo!`, and use |:TypstCompilerForceClear| only
after handling the external process yourself.

If motions, text objects, folds, indentation, package syntax, or conceal are
missing, check that the Typst Tree-sitter parser and shipped queries load in
`:checkhealth typst`.
Without the parser, project resolution, compile/watch, viewer/native preview,
diagnostics, quickfix, output locks, and most completion sources still work.
Syntax-aware conceal, folds, motions, text objects, and structural editing fall
back or remain disabled until the parser is available.

If Tree-sitter-backed features are stale after parser/query changes, run
|:TypstReloadState| or |:TypstClearCache| after confirming health. Rich conceal,
folds, motions, text objects, raw-code injections, and package syntax all depend
on a compatible parser/query pair.

If browser preview opens but source sync does not work, check the preview
backend capabilities. PDF viewing, browser preview, forward search, and inverse
search are separate capabilities in Typst workflows.

If preview stop is pending or failed, check |:TypstPreviewStatus| and
|:TypstLog|. Native preview, typst-preview.nvim delegation, and custom callback
providers have different stop guarantees; a pending provider stop is not treated
as confirmed process exit until the provider reports a terminal result.

If cached project data looks stale, run |:TypstReloadState| to re-resolve the
current buffer or |:TypstClearCache| to clear generated metadata selection,
package resources, symbol search caches, project index caches, and conceal
match caches.

If `:helptags` reports missing help tags, run a link/tag audit on `doc/typst.txt`.
Command argument alternatives should be written with commas, for example
`[toggle, add, remove]`, not literal `|` characters, because Vim help treats
pipe-delimited help tags as links.

ARCHITECTURE                                             *typst-architecture*

typst.nvim is organized around workflow ownership, not only feature names.
The intended ownership model is:

- project identity: `typst.project`, `typst.project.resolver`, and
  `typst.project.store`;
- buffer hook ownership: `typst.project.attachments`;
- live resource liveness migration: `typst.resources.session` and
  `typst.resources.supervisor`;
- generated output leases: `typst.resources.outputs`;
- compile/watch state: `typst.compiler`;
- compiler result fanout: `typst.compiler.fanout` and
  `typst.compiler.consumers`;
- diagnostic publication: `typst.diagnostics.publisher`;
- user presentation: commands, status reports, notifications, and health.

Project resolution should answer root, main file, buffer source, and project
key questions without owning compiler or preview shutdown. The ProjectStore
facade owns live projects, encoded keys, buffer membership, and prune
bookkeeping while `project.registry` remains the raw low-level map. Resource
modules summarize active compiler, preview, operation, diagnostic, and
output-lease state so prune, reset, exit, and force-clear paths do not need to
duplicate backend details.

The long-term directory target is documented in `docs/architecture.md`.
Contributor patches should prefer strengthening these boundaries before large
file moves:

- resolver code should not mutate the registry;
- attachment code should go through `project.attachments`;
- reset/exit/prune cleanup should go through `resources.supervisor`, which is
  the cleanup entry point while ownership migrates behind it;
- project code should not publish diagnostics directly;
- output-producing workflows should acquire/release leases through
  `resources.outputs`;
- compiler backends should route artifact, diagnostics, dependency, log, and
  event consumers through compiler fanout modules; viewer and preview refresh
  should route through `compiler.consumers` from the existing API/controller
  paths;
- only diagnostics publisher code should write compiler diagnostics with
  `vim.diagnostic.set`;
- compiler stop/timeout semantics should preserve unconfirmed writers until
  exit is confirmed or the user explicitly force-clears retained state.

PERFORMANCE                                                 *typst-performance*

The expensive paths are project discovery, project indexing, conceal rendering,
completion sources, Tinymist requests, and preview refresh. The defaults favor
a useful out-of-box workflow, but large repositories may need tighter settings.

Project import scanning is bounded by `project.import_scan_max_files`,
`project.import_scan_max_depth`, `project.import_scan_max_descendant_depth`,
and `project.import_scan_max_entries`. `project.import_scan_max_depth` controls
how many ancestor root candidates are scanned when the root was only the buffer
directory; `project.import_scan_max_descendant_depth` controls recursive
descent below each scan root when set, and defaults to unlimited traversal
bounded by the file and entry caps. It skips directory basenames listed in
`project.import_scan_skip_dirs` before spending filesystem-entry budget, is
kept in a short-lived cache keyed by path, root, config generation, root
metadata, and scan limits, and |:TypstClearCache| clears it immediately. Buffer
attach defers the scan so opening a leaf file can use a fast fallback first;
command paths force any pending scan before they operate.
When a scan root exceeds the entry cap, typst.nvim abandons that import-scan
attempt and falls back to later main-file heuristics before candidate files are
read.
If deferred import scanning is still too expensive, inspect |:TypstInfo|, lower
`project.import_scan_max_entries`, disable `project.import_scan`, or set a
`.typstmain`/`:TypstSetMain` decision.
For project indexing, `project.index.large_file_policy = "headings-only"` avoids
expensive label/reference/path scans for oversized unloaded files, but it still
reads those files to recover headings and local imports/includes.

Window feature application is idempotent by buffer and window signatures so
ordinary `WinEnter`/`BufWinEnter` events do not repeatedly reapply folds and
conceal when the relevant state has not changed. Conceal still uses
Tree-sitter and decoration-provider state, so large visible ranges should be
measured with |:TypstTelemetry| before changing cache rules.

Completion and Tinymist requests use generation, changedtick, cursor, timeout,
and waiter guards. Late async responses are ignored when the buffer changed or
the request no longer matches the active context.

Watch output is retained with bounded stdout/stderr history and a capped
pre-drain stream queue. If a broken provider floods output, typst.nvim
truncates or drops additional incoming chunks once the queue is full, marks the
watcher as truncated, and logs throttled warnings instead of allowing
unbounded memory growth.

==============================================================================
DEBUGGING                                                     *typst-debugging*

Use these commands in order when a workflow behaves unexpectedly:

1. |:TypstInfo| or `:TypstInfo!` for project root/main, provider, output,
   diagnostics policy, active resources, leases, and status details.
2. |:TypstStatusAll| or `:TypstStatusAll!` for all retained projects and
   copyable force-clear commands when a provider stop was unconfirmed.
3. |:TypstLog| for bounded lifecycle, provider, process, and callback errors.
4. |:TypstTelemetry| for recent timings and counters around setup, attach,
   import scanning, TOC follow, conceal, completion, and watch output.
5. `:checkhealth typst` for executable, Tree-sitter, Tinymist, viewer, preview,
   and attached-project checks.

Wrong-main problems should start with `root_source` and `main_source` in
|:TypstInfo|. Slow leaf-file opens usually point at import scanning. Missing
conceal/folds/motions usually point at Tree-sitter query/parser health. Preview
or viewer source-sync failures should be checked against backend capabilities:
normal Typst PDF output does not provide SyncTeX-style guarantees by itself.

When an external compiler provider times out or reports `stopped = false`,
typst.nvim treats the writer as unconfirmed. The active lease is retained,
status becomes `stopping_failed`, and |:TypstCompilerForceClear| is the explicit
escape hatch after the external process has been handled outside Neovim.

API STABILITY                                             *typst-api-stability*

The public Lua module is installed broadly for commands and integrations, but
the stable contract is intentionally narrow before 1.0. No namespace is stable
merely because it exists. Stability is decided by dotted symbols:

>
  require("typst").stable_symbols()
  require("typst").experimental_symbols()
  require("typst").contract()
<

Stable symbols currently cover setup/contract introspection, project attach
and main-file helpers, compiler compile/watch/stop/status/output helpers, and
viewer open/source-sync capability helpers. Installed editing, completion,
artifact, metadata, provider, navigation, preview-helper, development, and
reset APIs are experimental unless their exact dotted name appears in
`stable_symbols()`.

Internal implementation modules are not part of the user API even when they are
loadable. Treat `typst.core.*`, `typst.resources.*`,
`typst.project.services.*`, `typst.runtime.*`, and `typst.internal.*` as
internal unless a function is exposed through `require("typst")` and documented
in `API.md`.

Provider contracts are public extension points. Provider authors should prefer
the documented provider registry and `docs/provider-contracts.md` over calling
internal process, operation, resource, or project-service modules directly.

Project APIs that return project state return copied public snapshots, not live
service tables. This includes `project.attach()`, `project.detach()`,
`project.get()`, `project.projects()`, `project.reload_state()`,
`project.set_main()`, `project.snapshot()`, and `project.toggle_main().state`.
Mutating those tables never mutates typst.nvim's live project registry.
Before this hardening release, some public project methods returned live project
tables. They now return copied public snapshots. Code that only reads identity,
root, main, output, status, files, dependencies, diagnostics, and artifacts
should continue to work. Code that mutates services, buffers, resolutions, or
compiler state must move behind a provider, a public command/API call, or an
internal typst.nvim module.
Snapshots can be passed back into project-scoped public APIs while the backing
project instance is still live. Snapshot resolution checks both the project key
and a session-local instance token. If the project has been pruned, or if the
same root/main key has been recreated as a new project instance, that explicit
snapshot fails with `unknown_project_key` rather than operating on copied or
unrelated state.

The public Lua API is versioned. `api_version()` returns the current API level,
currently `1`; `version()` returns a table with the same level as `api` and
`api_version`; `contract()` returns the versioned API/event contract, including
documented `TypstEvent*` names, payload fields, namespace tiers, and internal
module prefixes. Stable API level 1 symbols are additive unless a migration is
documented. Before 1.0, stability is symbol-based: `project`, `compiler`, and
`viewer` are mixed namespaces with explicit stable entry points, while editing,
completion, artifact, metadata, provider, navigation, preview-helper,
development, and reset APIs are experimental unless promoted by exact dotted
name. `stable_symbols()` returns the exact stable list.
`experimental_symbols()` returns installed helper APIs that are intentionally
outside the stable compatibility contract for now. See |typst-api-stability|.
Earlier reset-phase docs used broad namespace stability language. That wording
has been narrowed before 1.0 without an API-level bump: installed namespaces
remain available, but demoted helpers are experimental unless their exact
dotted name appears in `stable_symbols()`.

Process-backed async calls such as export, eval, template init,
profile/test/bench/coverage, and rendered preview compiles return a pending
result table with `cancel()`. Cancellation marks the result as cancelled and
stops the originating process tree.
If graceful and forceful shutdown cannot prove the process exited, the
operation first becomes `orphaned-running`, then `orphaned-retained` after
bounded stop attempts so normal active-operation waits can continue.
Cancellation callbacks receive that unconfirmed result once. `on_finish()`
callbacks, final cleanup, and lease release still wait for a later real exit,
which reports `was_orphaned = true` and `exited_after_orphan = true` without
synthesizing `stopped = true`.
Compiler/watch runs are cancelled with `stop()` and `stop_all()`. Reset and
clear-cache paths cancel pending background probes such as Tinymist completion,
package info, font scans, and metadata version detection.
On Windows, normal compile/watch stop and restart paths target the process tree
with `taskkill /T` before falling back to direct process signaling. This matches
the reset/exit cleanup path and prevents wrapper-script children from surviving
ordinary |:TypstStop| calls.
Runtime reset clears global follow-buffer autocmds, deferred resolver tokens,
buffer attachment debounce state, and loaded completion/active conceal/
diagnostic caches through explicit runtime/cache lifecycle hooks. Stable
Tree-sitter parser callback guards are retained when needed to avoid duplicate
callback registration on live parsers. If active resources cannot be confirmed
stopped and `force` is not set, projects may be retained so late exits cannot
update discarded state.
Use `typst.reset({ force = true })` as the strongest in-process recovery path
after a stuck watch, preview, or provider callback. Without `force`, reset may
retain projects whose external resources could not prove terminal shutdown.
Inspect retained resources with |:TypstInfo!|, |:TypstStatusAll!|, and
|:TypstLog| before discarding them.

Output locks are file-backed guards for generated artifacts. |:TypstLocks|
lists locks and owner metadata when available. |:TypstCleanLocks| removes stale
locks only; |:TypstCleanLocks!| is for explicit recovery after verifying the
external writer is gone. |:TypstCompilerForceClear| discards typst.nvim's
retained provider handle and output lease for an unconfirmed provider, but it
does not kill or prove termination of the external process.

Cursor-sensitive Lua APIs use `bufnr`, `winid`, and `pos` to resolve the source
context. A non-current buffer needs an explicit `pos` or a `winid` that displays
that buffer; otherwise APIs that need a cursor position return no action or a
`position_required` result instead of reading the active window by accident.

Project-scoped public Lua wrappers use a shared no-project policy. Passive
inspection APIs such as `compiler.status()`, `compiler.current_output()`,
`viewer.preview_status()`, `project.services()`, and report helpers reuse an
attached project, an explicit `project`, or an explicit key (`key` or
`project_key`, with `key_encoded = true` for command-safe encoded keys); they
do not create scratch projects from dashboards, timers, statuslines, or other
non-Typst buffers, and they do not notify by default when no project exists.
Cleanup APIs such as `viewer.clean()` and `viewer.clean_preview()` also use
no-create resolution, but remain action APIs. When no project is available,
wrappers return `nil, { reason = "no_project", ... }` or a result table with
`ok = false` and `reason = "no_project"`. If an explicit key cannot be
resolved, wrappers return `unknown_project_key` or `ambiguous_project_key`
instead of `no_project`.

Action APIs such as compile, watch, preview, render, export, eval, navigation,
and semantic calls may resolve or create project state only for Typst source
buffers. Calls from a non-Typst buffer fail closed with the same `no_project`
reason instead of compiling an unintended main. Integrations should pass
`{ bufnr = typst_bufnr }`, `{ project = project }`, or an explicit project key
when the current buffer is not the Typst source. `viewer.capabilities()` is
project-free; preview capabilities are project-scoped. Viewer and preview
inverse-search wrappers also try `opts.path`/`opts.source_path` against loaded
buffers and existing project graphs. When an explicit source path is supplied
but is not associated with any loaded buffer or existing project graph, they
return `source_path_not_in_project` instead of falling back to the focused
project.

Opening and jumping use a separate destination-window option. File-target
navigation, context actions, package/source actions, and viewer or preview
inverse jumps open in the current window by default. Pass `open_winid` to make a
specific window receive the opened target. `jump_winid` and `target_winid` are
accepted aliases for integrations. `winid` continues to mean source window, not
destination window.

`status()` returns a table with `attached`, `bufnr`, `status`, `root`, `main`,
`main_name`, `output`, `output_name`, `profile`, `root_source`, `main_source`,
`cwd`, `command`, active process/watcher details, viewer/preview backend
details, `diagnostics`, current-buffer `words`, `characters`,
`characters_with_spaces`, `compiler_diagnostics`, `tinymist_lsp_backend`,
`tinymist_lsp_mode`, `tinymist_lsp_enabled`, `tinymist_lsp_attached`,
`buffers`, `dependencies`, `index_generation`, and `index_stats` fields when a
Typst project is attached. `index_stats` reports project-index collect, file,
and bibliography cache hits and misses. Pass `{ telemetry = true }` to include
`telemetry` and `telemetry_report`, matching the data shown by
|:TypstTelemetry|. The `status` field is read through the active compiler
provider's `status(project)` method.
`compiler_diagnostics` is one of `fallback_active`,
`fallback_suppressed_by_tinymist`, `always`, or `off`.
`statusline()` returns a compact string such as `Typst:success main.typ
[draft]`. Pass `{ words = true }` to append the current-buffer word count.

Package and symbol helpers accept `{ open = false }` to return normalized result
tables or URLs without opening a scratch buffer or browser. Without `query`,
cursor token resolution is used where applicable.

Provider helpers register named Lua providers for `compiler`, `format`, `lint`,
`grammar`, `viewer`, `picker`, `toc`, `index`, `export`, `eval`, `init`,
`profile`, `test`, `bench`, `coverage`, `semantic`, and `render`. Registered
names are accepted by the matching configuration keys, for example
`format.provider = "my-format"` or `viewer.provider = "my-viewer"`.

==============================================================================
PUBLIC API                                                        *typst-api*

The public API surface is documented in `API.md`. In short, public surfaces
are documented commands, the main `require("typst")` module functions, emitted
`User` events, configuration keys, and documented `<Plug>(typst-...)` mappings.

Internal modules under `lua/typst/` are implementation details unless they are
explicitly documented as public.

==============================================================================
EVENTS                                                            *typst-events*

The plugin emits these public `User` events:

- `TypstEventInitPre`
- `TypstEventInitPost`
- `TypstEventConfigChanged`
- `TypstEventProjectAttach`
- `TypstEventBufferDetach`
- `TypstEventProjectDetach`
- `TypstEventProjectPruned`
- `TypstEventCompileStarted`
- `TypstEventCompiling`
- `TypstEventCompileSuccess`
- `TypstEventCompileFailed`
- `TypstEventCompileStopped`
- `TypstEventCompilerForceCleared`
- `TypstEventPreviewStarted`
- `TypstEventPreviewForwarded`
- `TypstEventPreviewInverse`
- `TypstEventPreviewStopped`
- `TypstEventViewInverse`
- `TypstEventArtifactCreated`
- `TypstEventArtifactsCleaned`
- `TypstEventRenderCreated`
- `TypstEventTocCreated`
- `TypstEventTocActivated`
- `TypstEventQuit`

`TypstEventInitPre` and `TypstEventInitPost` include `first_setup = true` on
the first setup call and `reconfigure = true` on later setup calls. Plugin
managers that call `require("typst").setup()` after the runtime plugin loaded
should treat the later event as reconfiguration, not a second independent
startup. Reconfiguration also emits `TypstEventConfigChanged` after the new
configuration is installed and attached buffers are reapplied. Event order is
`TypstEventInitPre` -> `TypstEventInitPost` on first setup, and
`TypstEventInitPre` -> `TypstEventConfigChanged` -> `TypstEventInitPost` on
reconfiguration.

Project reassignments through public APIs such as |:TypstSetMain|,
|:TypstToggleMain|, lazy `project.get()`, or buffer reattachment emit
`TypstEventBufferDetach` for the old project and `TypstEventProjectAttach` for
the new project when the project key changes. `TypstEventProjectDetach` remains
emitted as a compatibility alias for the same buffer-detach moment; it does not
mean the project registry entry was removed. `TypstEventProjectPruned` fires
only when an empty project is removed from typst.nvim's registry.
`TypstEventProjectAttach` fires after project registry state is committed and
buffer project finalization has run, so handlers may inspect finalized project
state. If a non-critical finalizer fails, the attach event still fires with
`finalization_ok = false` and `finalization_error`; successful attach events
include `finalization_ok = true`. Reassignments that keep the same project key do not emit
duplicate project events.

The older event names remain emitted for compatibility:

- `TypstProjectAttach`
- `TypstBufferDetach`
- `TypstProjectDetach`
- `TypstProjectPruned`
- `TypstCompileStarted`
- `TypstCompileSuccess`
- `TypstCompileFailed`
- `TypstCompileStopped`
- `TypstCompilerForceCleared`
- `TypstDiagnosticsPublished`
- `TypstDiagnosticsCleared`
- `TypstViewOpened`
- `TypstViewForwarded`
- `TypstViewInverse`
- `TypstOutputCleaned`
- `TypstArtifactCreated`
- `TypstArtifactsCleaned`
- `TypstPreviewOpened`
- `TypstPreviewForwarded`
- `TypstPreviewInverse`
- `TypstPreviewStopped`
- `TypstRenderCreated`

The event `data` table contains `key`, `root`, `main`, `output`, `status`,
`provider`, `profile`, `cwd`, and `command`. `profile` and `command` are `nil`
before any profiled compile or background command has been run.
Project attach events add `event_kind`, `bufnr`, `buffer`, `reason`, and
`remaining_buffers`. Buffer detach events add `event_kind`, `bufnr`, `buffer`,
`reason`, `remaining_buffers`, and `project_pruned`. `TypstEventProjectPruned`
includes `event_kind`, `reason`, `remaining_buffers`, and `project_pruned`.
Project attach events may also include `resolution_pending = "import_scan"`.
Handlers that start watchers, previews, or external tools should either skip
pending attaches or call the public project API to force resolution before
acting; a later non-pending attach event is emitted when deferred import
scanning settles on a different main file.
`TypstEventCompilerForceCleared` includes `key_display`, `output`,
`released_lease`, `stopped`, `forced`, `discarded`, `reason`, and
`lease_owner`. `forced` is true only when bang/`force = true` bypassed the
`stopping_failed` guard.
`TypstDiagnosticsPublished` and `TypstDiagnosticsCleared` include
`diagnostics_count` and `diagnostic_buffers`.
`TypstViewOpened` also includes `viewer_provider`, `viewer_backend`, and may
include `viewer_command` and `viewer_cwd` when an external viewer executable is
used. `TypstViewForwarded` includes `viewer_provider`, `viewer_backend`, `line`,
and `column`. `TypstViewInverse` includes `viewer_provider`, `viewer_backend`,
`path`, `line`, and `column`.
`TypstPreviewOpened` and `TypstPreviewStopped` also include `backend`,
`preview_backend`, `preview_command`, `preview_cwd`, `preview_active`, and may
include `mode` or `preview_mode`. Artifact-created events include artifact
metadata such as `id`, `path`, `canonical_path`, `format`, `signature`,
`freshness`, `reason`, `producer`, and `preview_export`. Artifact-cleaned
events include `deleted`, `skipped`, `failed`, and `producer`.
`TypstRenderCreated` includes `kind`, `path`, `source`, `format`, and may
include `page`. TOC events include `items`. Initialization events include
`provider`, `did_setup`, `first_setup`, `reconfigure`, and `setup_once`; quit
events include `provider` and `projects`.
